# MenuLive: движок 2.0 и витрина Brest. Дизайн

**Дата:** 2026-09-06
**Статус:** утверждён в обсуждении, ожидает ревью текста спеки
**Этап:** 1 из 4 (см. дорожную карту)

## 1. Контекст и цель

Проект: веб-AR-меню. Гость сканирует QR, открывает страницу в браузере, наводит камеру
на бумажное меню, и поверх страницы появляется видео блюда. Сейчас в проде 5 страниц
(MU, Balzac, Afra, Bravo, Brest), каждая - полная копия `index.html` со своим конфигом.
Все видео блюд - стоковые заглушки, у Brest таргет скомпилирован из чужого флаера.

Цель этапа 1: превратить прототип в продукт, который не стыдно показывать рестораторам
и снимать в рекламный ролик. Витрина - выдуманный ресторан Brest (можно сочинять что угодно,
никого не заденем). Продукт получает имя **MenuLive**.

Выбранный подход (вариант А из обсуждения): общий движок + «парящие» блюда через luma-key +
экран приветствия + подсказка сканирования + карточка блюда со списком для официанта.

### Не делаем на этапе 1
- Не трогаем страницы MU, Balzac, Afra, Bravo (мигрируют на этапе 4).
- Не делаем бэкенд, аккаунты, реальную отправку заказов и аналитику (только заглушка событий).
- Не делаем лендинг и домен (этап 4).
- Не делаем контент Brest (бренд, меню-таргет, видео блюд): это этап 2. На этапе 1 нужны
  только 1-2 тестовых видео на чёрном фоне для проверки шейдера.

## 2. Дорожная карта (4 этапа, у каждого своя спека и план)

1. **Движок MenuLive 2.0 + миграция Brest** (эта спека).
2. **Контент Brest:** концепция кухни, логотип, A4-меню с тарелкой-рамкой, 6-8 блюд RU/UZ,
   AI-видео блюд на чёрном фоне, `.mind`, миниатюра, QR.
3. **Ролик MenuLive:** сценарий RU на 60-75 с, съёмочный лист (экран iPhone + камера со стороны),
   озвучка и музыка, моушн-графика из HTML через ffmpeg, интерактивный финал (QR + меню на экране,
   зритель пробует сам), вертикальная нарезка 9:16 на 30 с, затем версия UZ.
4. **Лендинг и масштабирование:** домен menulive.uz, лендинг с роликом и контактами,
   миграция остальных ресторанов на движок.

Порядок жёсткий: ролик снимается только после этапов 1 и 2.

## 3. Архитектура

### 3.1 Файлы

```
engine/
  main.js          точка входа: грузит конфиг, применяет тему, собирает сцену и UI, связывает события
  ar.js            A-Frame: регистрация компонентов и шейдеров, построение <a-scene>, события found/lost/ready
  player.js        один <video>: смена источника, состояние загрузки, лоадер, фоновый прогрев
  ui.js            DOM: приветствие, подсказка, вкладки, лента блюд, карточка, плашка и лист для официанта, тосты
  core/config.js   валидация конфига и значения по умолчанию (чистая функция)
  core/i18n.js     выбор строки по языку с запасным вариантом, склонения (чистые функции)
  core/format.js   формат цен и веса (чистая функция)
  core/order.js    список для официанта: добавить, убавить, итог, сериализация (чистый класс)
  core/stage.js    расчёт размеров и позиции сцены (чистая функция)
  menulive.css     стили UI на CSS-переменных темы
  package.json     {"type": "module"}, чтобы node --test импортировал core/*.js
restaurants/
  brest.json       конфиг ресторана (только данные)
assets/brest/      logo.png, menu.mind, menu-preview.jpg, qr.png, видео и постеры блюд
test/              *.test.js на node --test для core/*
test/stage.html    служебная страница: плоскость с luma-key поверх фото меню, без камеры
brest.html         тонкая страница: A-Frame 1.5.0, MindAR 1.2.5, engine/main.js?v=N, data-config
```

ES-модули без сборщика и без новых зависимостей. A-Frame и MindAR подключаются классическими
скриптами до модуля движка (модули выполняются после них по умолчанию).

`.gitignore`: правила `package.json` и `package-lock.json` заякорить в корень (`/package.json`,
`/package-lock.json`), чтобы `engine/package.json` попал в репозиторий. Корневой package.json
остаётся локальным, как и сейчас.

### 3.2 Ответственность модулей и интерфейсы

- `main.js`: `boot()` читает `document.body.dataset.config`, делает `fetch`, вызывает
  `validateConfig`, применяет тему (`--ml-bg`, `--ml-accent`, `--ml-accent2`, `--ml-text`),
  создаёт `UI`, `Player`, `AR`, связывает события. Определяет режимы `?preview=1` и `?debug=1`.
- `ar.js`: `createScene(config, stageSize) -> { el, start(), on(event, fn) }`. События:
  `ready`, `found`, `lost`, `error(kind)`. Регистрирует `smooth-track`, `pinch-zoom`
  (переносятся из текущего `index.html` без изменений поведения) и шейдер `ml-key`.
- `player.js`: `Player(videoEl) -> { load(dish), play(), pause(), setMuted(bool), on('loading'|'metadata'|'ready'|'error') }`.
  Готовность = событие `timeupdate` с `currentTime > 0.05` (как в текущей версии: лоадер прячется,
  только когда кадры реально рендерятся). Событие `metadata(aspect)` приходит на `loadedmetadata`;
  `main.js` по нему пересчитывает размер сцены через `core/stage.js` и вызывает `AR.setStageSize()`,
  так что блюда с разными пропорциями видео не искажаются. `prefetch(urls)` - последовательный `fetch`
  в HTTP-кэш после первого `playing`, пропускается при `navigator.connection.saveData`.
- `ui.js`: `UI(root, config, i18n) -> { showWelcome(onStart), showHint(), hideHint(), setFound(bool),
  renderCategories(activeId), renderDishes(categoryId, activeId), renderCard(dish, qty),
  renderOrderPill(count, total), openOrderSheet(), showWaiterScreen(), toast(text), showError(kind) }`.
  Все тексты интерфейса берутся из словаря `ui.js` по текущему языку.
- `core/order.js`: `Order(restaurantId)`: `add(dishId)`, `inc`, `dec`, `remove`, `count`, `total(dishes)`,
  `toJSON`, `static fromJSON`. Хранение: `sessionStorage['menulive:order:<id>']`.
- Заглушка аналитики: `track(name, data)` в `main.js` пишет в `console.debug` в режиме debug,
  иначе ничего. Точка расширения на будущее, не функция продукта.

### 3.3 Поток данных

QR -> `brest.html` -> `main.boot()` -> конфиг -> тема + UI(приветствие) -> тап «Открыть камеру»
(жест пользователя: `video.play().then(pause)` для iOS, затем `AR.start()`) -> `ready` -> подсказка
-> `found` -> `Player.load(активное блюдо)` -> сцена видима -> взаимодействие с UI меняет блюдо
и список -> `lost` -> пауза видео, сцена скрыта, UI приглушён -> `found` снова -> продолжить.

```json
                "smoothFactor": 0.02, "posThreshold": 0.005, "rotThreshold": 0.008 },
  "languages": ["ru", "uz"],
  "defaultLang": "ru",
  "currency": { "ru": "сум", "uz": "so'm" },
  "waiter": { "url": "" },
  "categories": [
    {
      "id": "galettes",
      "name": { "ru": "Галеты", "uz": "Galetlar" },
      "dishes": [
        {
          "id": "complete",
          "name": { "ru": "Галета Комплет", "uz": "Komplet galeta" },
          "desc": { "ru": "гречневый блин, ветчина, яйцо, эмменталь", "uz": "..." },
          "price": 68000,
          "weight": "320 г",
          "video": "assets/brest/complete.mp4",
          "poster": "assets/brest/complete.jpg",
          "audio": false,
          "key": "luma"
        }
      ]
    }

```

Правила:
- Единицы сцены: ширина таргета = 1 (соглашение MindAR), `x`,`y` - смещение центра сцены от центра
  таргета, `w` - ширина сцены. Высота вычисляется из пропорций видео (`videoWidth/videoHeight`),
  если `h` не задан явно. Сцена лежит на `z = 0.01`.
- `key` на уровне блюда переопределяет `stage.key`. Допустимые значения: `luma`, `chroma`, `none`.
- Цены - целые числа в сумах. Формат: разряды через пробел, валюта из `currency` по языку:
  `68 000 сум` / `68 000 so'm`.
- Строки `{ "ru": ..., "uz": ... }`. Выбор: текущий язык -> `defaultLang` -> первый непустой.
- `validateConfig` возвращает конфиг с подставленными значениями по умолчанию или бросает ошибку
  с указанием пути к полю (`categories[0].dishes[2].video`).
- Обязательные поля: `id`, `name`, `logo`, `target.mind`, `target.preview`, `stage.w`,
  `categories[].id`, `categories[].name`, `dishes[].id`, `dishes[].name`, `dishes[].price`, `dishes[].video`.

## 5. AR-часть

### 5.1 Сцена
`<a-scene mindar-image="imageTargetSrc: <mind>; maxTrack: 1; filterMinCF; filterBeta; warmupTolerance;
missTolerance" vr-mode-ui="enabled: false" device-orientation-permission-ui="enabled: false"
loading-screen="enabled: false" renderer="colorManagement: true" color-space="sRGB">` создаётся
динамически после загрузки конфига. Внутри: камера, `<a-entity mindar-image-target="targetIndex: 0"
smooth-track=...>` и в ней:
- `#stage` - `<a-plane>` с материалом `shader: ml-key; src: #ml-video; ...` и `pinch-zoom`;
- `#stage-loader` - тонкое кольцо (`<a-ring>`) цвета акцента с анимацией вращения, видимо, пока
  плеер в состоянии `loading` дольше 300 мс.

Никаких чёрных плоскостей-заглушек и верхнего промо-видео.

### 5.2 Шейдер `ml-key`
Регистрируется через `AFRAME.registerShader`. Uniforms: `src` (map), `mode` (0 none, 1 luma, 2 chroma),
`threshold`, `smoothing`, `keyColor`, `similarity`, `smoothnessC`, `spill`, `feather`.
- luma: `luma = dot(rgb, vec3(0.299, 0.587, 0.114)); alpha = smoothstep(threshold, threshold + smoothing, luma)`.
- chroma: `d = distance(rgb, keyColor)` в YUV-подобном пространстве; `alpha = smoothstep(similarity, similarity + smoothnessC, d)`;
  подавление зелёного разлива на величину `spill`.
- feather: радиальное затухание альфы от `1 - feather` к `1` по расстоянию от центра плоскости.
- `transparent: true`, `depthWrite: false`, `side: double`.

### 5.3 Стабилизация
Компоненты `smooth-track` и `pinch-zoom` переносятся из текущего `index.html` как есть.
Параметры MindAR и smooth-track берутся из `config.tracking` со значениями по умолчанию,
равными текущим продовым (см. пример конфига). Дополнительно: двойной тап по сцене сбрасывает масштаб.

### 5.4 Поведение при found/lost
- `found`: `navigator.vibrate?.(30)`, сцена `visible = true`, анимация `scale 0.9 -> 1` и `opacity 0 -> 1` за 300 мс,
  плеер `play()`. Первый захват вызывает загрузку активного блюда, повторный - только `play()`.
- `lost`: сцена `visible = false`, плеер `pause()`, UI получает класс `dimmed`, но остаётся интерактивным.

## 6. Интерфейс и путь гостя

### 6.1 Состояния
`boot -> welcome -> starting -> scanning -> found <-> lost`, плюс терминальные `error(kind)`:
`config`, `camera-denied`, `camera-unavailable`, `webgl`, `desktop`.

### 6.2 Экраны и элементы
1. **Приветствие.** Фон `--ml-bg`, логотип, заголовок «Наведите камеру на меню, и блюда оживут»,
   переключатель языка (сохраняется в `localStorage['menulive:lang']`), кнопка «Открыть камеру»
   с кольцом прогресса в состоянии `starting`, внизу «Работает на MenuLive».
2. **Подсказка сканирования.** Показывается в `scanning`: анимированные уголки в центре,
   миниатюра `target.preview`, текст «Наведите на страницу меню». Через 8 с суммарного сканирования
   добавляется «Держите меню ровно, нужно больше света». На `found` скрывается; после `lost`
   появляется через 1.5 с, если захват не вернулся.
3. **Вкладки категорий** сверху, горизонтальная прокрутка при переполнении, активная выделена.
   Справа кнопки языка и звука (звук только если у активного блюда `audio: true`).
4. **Лента блюд** внизу над карточкой: чипы «название · цена», горизонтальная прокрутка, активный чип
   подсвечен и прокручивается в видимую область.
5. **Карточка блюда:** название, цена, вес, описание в две строки (тап раскрывает), кнопка «Добавить».
   После добавления кнопка становится степпером «− n +».
6. **Плашка списка** над карточкой, когда позиций больше нуля: «2 блюда · 136 000 сум». Тап открывает лист.
7. **Лист для официанта:** позиции со степперами, итог, кнопки «Показать официанту» и (если задан
   `waiter.url`) «Написать». «Показать официанту» открывает полноэкранный контрастный список крупным
   шрифтом с логотипом ресторана и кнопкой «Готово». Никакой отправки данных: гость показывает экран официанту.
8. **Тосты:** «Добавлено», ошибки загрузки видео («Не удалось загрузить видео, проверьте интернет»).
9. **Ошибки:** `camera-denied` - экран с инструкцией для iOS и Android и кнопкой «Повторить»;
   `desktop` (нет задней камеры при широком экране) - «Откройте на телефоне» и картинка `config.qr`;
   `config` - «Меню временно недоступно» с технической строкой ошибки мелким шрифтом.

Смена языка перерисовывает все тексты немедленно. Склонения счётчика: «1 блюдо / 2 блюда / 5 блюд»
и `1 ta taom` для UZ (функция в `core/i18n.js`).

### 6.3 Визуальный язык
Тёмные панели `rgba(bg, 0.75)` с `backdrop-filter: blur(12px)`, акцент `--ml-accent`, скругления 16-20 px,
системный шрифт, анимации 200-350 мс `ease-out`, `-webkit-tap-highlight-color: transparent`.
Служебные элементы A-Frame (`.a-enter-vr` и прочие) скрыты, как сейчас.

### 6.4 Служебные режимы
- `?preview=1`: без камеры и без `<a-scene>`. Фон - `target.preview` во весь экран, поверх области сцены
  обычный `<video>` с `mix-blend-mode: screen` (приближение luma-key для дизайна и записи экрана).
  Весь UI в состоянии `found`. Нужен для скриншотов во встроенном браузере и для ролика.
- `?debug=1`: оверлей с FPS, состоянием трекинга и плеера, ползунки `threshold`, `smoothing`, `feather`
  с живым применением к шейдеру. Значения выводятся, чтобы перенести их в конфиг.

- **Тесты логики:** `node --test test/` (Node 25 локально, без зависимостей):
  `config.test.js` (принимает пример, отклоняет отсутствие обязательных полей с путём, подставляет

  (`68 000 сум`, `68 000 so'm`), `order.test.js` (add/inc/dec/remove/count/total, сериализация),
  `stage.test.js` (размер и позиция сцены из конфига и пропорций видео).
- **Шейдер и UI без телефона:** `test/stage.html` (статичная A-Frame-сцена с `ml-key` поверх фото меню,
  тестовое видео на чёрном) и `brest.html?preview=1`. Проверяю скриншотами во встроенном браузере.
- **На устройствах (чек-лист для пользователя):** iPhone Safari и Android Chrome по выложенной странице:
  разрешение камеры и повтор после отказа, автозапуск после «Открыть камеру», звук, захват печатного A4,
  захват меню с экрана ноутбука, потеря и повторный захват, смена языка, список для официанта,
  переживание перезагрузки страницы (список в sessionStorage).
- **Бюджет:** видео блюда до 3 МБ, появление блюда не позже 2 с после захвата на 4G, старт камеры
  не дольше 3 с после тапа.

## 8. Требования к ассетам (вход для этапа 2)

- **Видео блюда:** H.264 High, `yuv420p`, 1280x720 или 1080x1080, 25 fps, 5-8 с, бесшовная петля,
  фон чистый чёрный (RGB не выше 8/255) для `luma` или чистый зелёный для `chroma`, блюдо ярко освещено,
  без тёмных теней на фоне, размер до 3 МБ, `-movflags +faststart`, звук AAC опционально (`audio: true`).
- **Постер:** JPG 640 px по ширине, первый кадр.
- **Меню-таргет:** A4 портрет, 300 dpi, много контрастных деталей по всей площади (требование MindAR),
  тарелка-рамка с подписью «наведите камеру» в месте сцены, без больших однотонных полей.
  Компиляция: `node compile.mjs assets/brest/menu.png assets/brest/menu.mind`.
- **Миниатюра таргета:** JPG 480 px по ширине для подсказки сканирования.
- **Логотип:** PNG с прозрачностью, 512 px.

## 9. Выкатка

- Ветка `engine-v2`, коммит на каждую задачу плана, без соавторов в сообщениях коммитов.
- Прод меняется в одном месте: `brest.html`. Остальные страницы не трогаются.
- `deploy/nginx-armenu.conf`: добавить `location ~* \.json$ { add_header Cache-Control "no-cache"; }`
  и долгий кэш для `.js`/`.css`; версия движка передаётся строкой `?v=N` в `brest.html`.
- Деплой только через git: `git push`, затем `git pull` на сервере. Никакого редактирования на сервере.
- Локальная проверка: любой статический сервер по http на localhost (камера доступна на localhost без TLS),
  `file://` не подходит из-за `fetch` конфига.

## 10. Риски

1. **Luma-key съедает тёмные части блюда.** Яркие рендеры на чистом чёрном, режим `chroma` для тёмных блюд,
   `feather`. Проверить на первых двух видео до генерации остальных.
2. **AI-видео блюд: качество и кредиты.** Стоимость выясняется первым тестовым клипом (vidIQ, 1076 кредитов);
   запасной путь: инструменты Google пользователя или съёмка настоящей еды на чёрной ткани.
3. **Захват с экрана ноутбука** (интерактивный финал ролика): блики и муар. Проверить рано;
   запасной вариант для встреч: распечатанные A4.
4. **iOS: автозапуск и звук.** Закрывается жестом на кнопке «Открыть камеру», `playsinline`, `muted` на старте.
5. **Динамическое создание `<a-scene>`** после fetch: проверить, что MindAR корректно инициализируется
   на уже готовом DOM (ожидается, что да; иначе конфиг встраивается в HTML и сцена статична).
